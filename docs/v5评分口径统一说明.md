# v5 评分口径统一说明

> 决策日期：2026-08-10

## 结论

项目只保留一套正式信用评分口径：`backend/app/ml/` 中的 FastAPI v5 评分引擎。`v5_current` 是当前线上/演示口径；`legacy_acceptance` 仅用于兼容历史验收数据，不得作为新功能入口。

结构化 SQLite 只承担数据样本和后续 ETL 数据源的角色，不计算、不存储最终评分。

## 已移除的旧链路

- 删除独立的结构化简化评分脚本；
- 删除该脚本生成的 CSV 评分结果；
- 从 SQLite 数据库及 SQL schema 中删除评分卡、额度映射、人工复核规则和评分结果表；
- 删除将旧简化公式描述为仍可保留方案的临时说明和分享截图。

保留的 SQLite 内容包括商户基础信息、财务税务快照、发票校验、月度经营序列及税务汇总视图，原始测试数据没有删除。

## 系统调用边界

```text
结构化/非结构化数据
        ↓ 字段清洗与映射
MerchantAnalysisRequest
        ↓
POST /api/v1/ml/score
或 POST /api/v1/ml/full-analysis
        ↓
唯一的 v5 评分、额度、复核与分析结果
        ↓
前端展示
```

前端、SQLite 脚本和数据适配器均不得复制 v5 权重、阈值或额度公式。未来如果更新评分规则，只修改后端评分引擎及其测试，避免再次出现两套结果。
