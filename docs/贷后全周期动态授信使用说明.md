# 贷后全周期动态授信使用说明

## 1. 功能定位

本模块把现有“一次性首次授信”扩展为可连续演示 12 个月的贷后动态授信闭环：

1. 生成当月经营、还款、额度使用和资金用途表现；
2. 重新运行现有经营信用评分、异常交易识别和资金缺口预测；
3. 形成提额、维持、降额、冻结新增提款或人工复核建议；
4. 保存每月快照、原因码、预警与额度历史；
5. 由银行审核员批准额度调整，商户只能补充材料或异常说明；
6. 展示数据来源、授权状态、同步时间和核验状态。

所有轨迹、阈值、银行数据和平台接口均为竞赛模拟，不代表工商银行真实业务规则或真实生产系统。

## 3. 推荐演示路径

### M001：稳定经营后提额

1. 选择 `M001 · 稳定经营`；
2. 连续点击两次“推进到下个月”，进入贷后第三个月；
3. 查看连续三个月按期还款、流水增长和正常额度使用的原因码；
4. 点击“批准系统建议”；
5. 顶部“当前生效额度”和额度历史立即更新；
6. 继续推进月份，可观察批准后的 90 天冷却约束。

### M002：快速成长提额

订单、流水与额度使用率同步增长，第三个月触发阶段性提额建议，体现资金需求与成长性的结合。

### M003：经营恶化降额和冻结

推进到第三个月可看到流水连续下降触发降额建议；继续推进会出现退款、资金缺口和还款逾期，严重逾期后冻结新增提款。降额建议始终不得低于未偿本金。

### M004：平台授权到期

推进到第三个月后，经营平台数据源显示“授权已到期”，复评进入数据质量门控和人工复核。点击“模拟续期授权”后，接口同步状态恢复；商户仍可在“商户补充端”提交他行流水作为辅助证据。

### M005：高风险异常交易

首月即模拟交易回流、相同整数金额和订单关联缺失，异常引擎输出高风险，系统立即冻结新增提款并进入人工调查。额度本身不会被直接压到未偿本金以下。

## 4. 页面说明

### 银行贷后监测台

- 当前额度、未偿本金、可用额度和经营信用评分；
- 本月模型候选额度、政策建议额度和最终动作；
- 审核员“批准建议、维持额度、升级人工核查”操作；
- 评分与生效额度变化曲线；
- 三套模型版本和当月输出；
- 数据来源、授权期限、最近同步和质量状态；
- 月度快照表、预警时间线及竞赛政策说明。

### 商户补充端

商户可补充：

- 他行流水；
- 经营合同；
- 资金用途证明；
- 异常情况说明。

商户提交的信息标记为 `MERCHANT_SUBMITTED_SIMULATED` 和“待核验”，不会直接改变额度，需与银行内部数据、授权平台数据或客户经理核查交叉验证。

## 5. 数据获取与频率

| 数据来源 | 示例 | 模拟频率 | 决策作用 |
|---|---|---|---|
| 银行内部 | 贷款余额、提款、还款、逾期 | 实时事件或 T+1 | 硬事实，主要依据 |
| 工行回款账户 | 经营流水、资金流向、异常交易 | T+1 | 自动监测与异常证据 |
| 经授权平台 | 订单、退款、核销、评价 | 每日或每月 | 经营表现与真实性 |
| 商户补充 | 他行流水、合同、用途证明、说明 | 按需或风险触发 | 辅助证据，待核验 |
| 人工核验 | 电话回访、材料核查、现场检查 | 风险触发 | 冲突和高风险兜底 |

风险事件可以持续监测，但完整额度复评按月运行；不会因为单笔交易或某一天营业额变化就实时改变额度。

## 6. 动态额度规则

规则集中在 `backend/app/services/postloan_service.py`，版本为 `postloan_competition_policy_v1`：

- 提额：连续三个月按期还款、无高风险异常、数据质量满足要求、流水稳定增长、额度使用合理；单次最多 15%，批准后执行 90 天冷却期；
- 维持：经营正常但尚未满足连续良好表现，或资金需求不足；
- 降额：还款压力、退款率升高、现金缺口高或流水连续下降；不得低于未偿本金；
- 冻结：高风险异常、严重逾期或资金用途风险；只冻结新增提款，不模拟要求立即清偿；
- 人工复核：平台授权到期、数据缺失、主体冲突或模型置信度低。

三套模型只产生分值与证据，状态机负责政策约束，LLM 只允许解释现有结果，不得决定额度。

## 7. API

| 方法 | 接口 | 作用 |
|---|---|---|
| GET | `/api/v1/post-loan/merchants/{merchant_id}/timeline` | 获取贷款账户、数据来源、月度快照、预警和当前复评 |
| POST | `/api/v1/post-loan/merchants/{merchant_id}/advance-month` | 推进一个月并重新运行三套引擎 |
| POST | `/api/v1/post-loan/merchants/{merchant_id}/reset` | 恢复到贷后第一个月 |
| POST | `/api/v1/post-loan/merchants/{merchant_id}/submissions` | 商户提交补充材料或异常说明 |
| POST | `/api/v1/post-loan/merchants/{merchant_id}/sources/{source_id}/authorization` | 模拟外部数据授权续期或撤销 |
| POST | `/api/v1/post-loan/reviews/{review_id}/decision` | 批准调整、维持额度或升级人工复核 |
| GET | `/api/v1/post-loan/alerts` | 汇总五个商户当前已经产生的预警 |

Swagger 启动后可在 `http://127.0.0.1:8000/docs` 查看完整请求和响应模型。

## 8. 当前实现边界

- 12 个月轨迹由确定性函数生成，进程重启后恢复初始状态；
- 贷后审核记录当前保存在后端进程内，没有连接真实数据库；
- 页面中的银行、平台、商户材料和人工核验均明确标记为模拟；
- 当前没有真实逾期/违约标签，不能把经营评分宣传为真实 PD 模型；
- 真正生产化需要身份认证、角色权限、持久化数据库、消息队列、接口签名、数据授权与审计日志。
