### 1. 锁定MVP范围

产品需求文档，明确：

-   谁使用；

-   解决什么问题；

-   完整用户流程；

-   必须实现的页面；

-   必须输出的结果；

-   本阶段明确不做什么。

建议首版只保证一条主流程：

> 商户提交材料 → 系统分析 → 输出模拟授信及消费策略 → 银行端持续监控。

### 2. 完成数据字典

把此前讨论的数据整理为统一表格，每项注明：

-   字段名称；

-   数据来源；

-   商户填写、上传还是授权；

-   文件格式；

-   时间范围；

-   是否必填；

-   如何计算；

-   缺失时如何处理。

这是整个系统最重要的基础。数据字典不确定，前端、后端和模型都会反复返工。

### 3. 明确评分与输出规则

在写代码前确定：

-   哪些指标影响风险；

-   哪些指标影响经营质量；

-   哪些指标影响成长潜力；

-   哪些情况直接触发人工审核；

-   如何从评分映射到额度区间；

-   如何从问题映射到消费策略。

首版不需要规则非常精准，但必须**可解释且前后一致**。

### 4. 准备测试商户

至少准备三个完整案例，每个案例包含：

-   基础信息；12个月经营数据；收款流水；合同或发票；

-   用户评价与投诉；经营计划；社交媒体主页

-   预期系统输出。

这些案例既是演示数据，也是开发测试标准。

### 5. 完成低保真原型

先画页面，不急着写代码。建议至少包含：

1.  商户申请首页；

2.  数据填写与上传页；

3.  分析进度页；

4.  授信与经营报告页；

5.  消费促进方案页；

6.  银行监控仪表盘。

-   模拟额度；

-   经营问题；

-   消费策略；

-   预警状态。

第三周结束标准：**系统具备申请、分析、策略和监控四个完整环节。**
