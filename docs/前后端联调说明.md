# 前后端联调说明

> 当前接口版本：0.4.0
> 分工边界：本文只约定数据和交互状态，不规定页面视觉、组件库或布局实现。

## 1. 推荐调用方式

前端综合分析页优先调用：

```text
POST /api/v1/ml/full-analysis
```

它一次返回经营评分、交易异常和资金缺口三类结果。三个独立接口继续保留，适合局部刷新或单模块页面：

| 接口 | 用途 |
|---|---|
| `POST /api/v1/ml/score` | 只重新计算经营评分与额度 |
| `POST /api/v1/ml/anomalies` | 只重新检测交易异常 |
| `POST /api/v1/ml/cash-gap` | 只重新预测资金缺口 |
| `POST /api/v1/ml/full-analysis` | 综合分析页首选，一次返回全部结果 |
| `POST /api/v1/materials/parse` | 上传文件级校验与竞赛模拟解析 |
| `GET /api/v1/materials/demo/{merchant_id}/{group}` | 下载 M001/M005 内置演示材料 |

请求体结构：

```json
{
  "application": {
    "social_credit_code": "18位统一社会信用代码",
    "operating_address": "经营地址",
    "legal_name": "法人姓名",
    "contact_phone": "手机号",
    "identity_verified": true,
    "uploaded_data_groups": ["cashflow", "statement", "tax", "plan"],
    "authorized_sources": ["bank", "meituan", "enterprise"],
    "consent_confirmed": true,
    "consented_at": "2026-08-11T08:00:00Z",
    "materials": [
      {
        "material_id": "MAT-M001-CASHFLOW-xxxxxxxx",
        "merchant_id": "M001",
        "group": "cashflow",
        "file_name": "M001_cashflow_12m.xlsx",
        "media_type": "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        "size_bytes": 57169,
        "sha256": "64位文件哈希",
        "parse_status": "PARSED",
        "simulated": true,
        "completeness_score": 98,
        "period_months": 12,
        "subject_match": true,
        "extracted_metrics": [],
        "findings": [],
        "warnings": []
      }
    ]
  },
  "merchant": {},
  "anomaly": {},
  "cash_gap": {}
}
```

`application` 和 `merchant` 必填。`application` 记录身份核验、已解析材料、资料完整性和授权证据。完整分析必须至少包含 `license`、`cashflow`、`statement`、`tax`、`plan` 五组已解析材料；`asset` 为可选补充。材料的 `merchant_id`、资料组和 `uploaded_data_groups` 不一致时返回 422。`anomaly`、`cash_gap` 可为 `null` 或省略，未运行模块通过 `module_states` 和 `data_warnings` 告知前端。

材料上传请求采用 Base64 JSON，单份上限 5 MB。后端真实校验扩展名、文件大小、PDF/Office/图片签名并计算 SHA256；当前 OCR 和指标提取使用案例固定规则，必须展示 `simulated: true`，不能对外声称已接入真实银行或税务系统。

## 2. 综合响应的页面映射

| 页面区域 | 推荐读取字段 |
|---|---|
| 商户标题 | `score.merchant_name`、`merchant_id`、`generated_at` |
| 总体风险状态 | `overall_risk` |
| 信用分主卡片 | `score.operating_credit_score`、`score.credit_grade` |
| 最终授信动作 | `overall_decision` |
| 评分模块决策 | `score.decision`，仅用于银行内部解释，不能替代总体动作 |
| 授信决策卡片 | `overall_decision`、`score.limit.recommended_limit`、`score.confidence` |
| 维度雷达图 | `score.dimensions` |
| 主要优势/风险 | `score.positive_reasons`、`score.negative_reasons` |
| 人工审核列表 | `score.review_required`、`score.review_rules` |
| 异常概览 | `anomaly.anomaly_score`、`anomaly.risk_level`、`anomaly.confidence` |
| 异常证据表 | `anomaly.rule_hits[].message`、`evidence_transaction_ids` |
| 资金概览 | `cash_gap.max_p50_funding_gap`、`max_p90_funding_gap`、`risk_level` |
| 资金缺口图 | `cash_gap.forecasts[].forecast_month`、`p50_funding_gap`、`p90_funding_gap` |
| 现金余额图 | `p50_ending_cash`、`p90_ending_cash`、`cash_gap.minimum_cash_balance` |
| 缺口驱动 | `cash_gap.drivers` |
| 数据不足提示 | `module_states`、`data_warnings` |
| 材料证据链 | `material_evidence[].material_id`、`sha256`、`completeness_score`、`subject_match`、`extracted_metrics`、`warnings` |

`pd_12m = null` 且 `pd_status = UNCALIBRATED` 是当前正确状态。页面应显示“真实违约概率待历史数据校准”，不能把经营信用分换算成违约概率。

## 3. 状态语义

### 总体风险

| 值 | 页面语义 |
|---|---|
| `LOW` | 当前未发现显著风险 |
| `MEDIUM` | 存在关注项，建议补充观察 |
| `HIGH` | 存在较高经营或流动性风险 |
| `MANUAL_REVIEW` | 命中人工审核门控，不自动作出授信结论 |

### 模块状态

| 值 | 页面处理 |
|---|---|
| `READY` | 正常渲染模块结果 |
| `NOT_PROVIDED` | 展示缺资料空状态，不展示为“低风险”或 0 分 |

异常识别的 `HIGH` 会把综合结果转为 `MANUAL_REVIEW`，但异常模型本身不能直接拒贷。资金缺口 `HIGH` 表示流动性风险较高，不等同于交易欺诈。

### 最终动作

| 值 | 页面语义 |
|---|---|
| `APPROVE` | 综合风险为低且评分模块建议通过 |
| `MANUAL_REVIEW` | 任一模块出现中高风险或命中复核规则，转人工处理 |
| `DECLINE` | 评分模块明确暂不建议授信 |

结果页标题必须读取 `overall_decision`，不能把 `score.decision` 与 `overall_risk` 拼成互相矛盾的结论。

## 4. 前端错误处理

| HTTP 状态 | 含义 | 推荐页面动作 |
|---|---|---|
| `200` | 分析成功，包括部分模块未提供数据 | 正常渲染并读取 `data_warnings` |
| `422` | 字段缺失、材料格式错误、月份不足或商户编号不一致 | 表单校验读取 `detail[].loc`；材料接口也可能直接返回字符串 `detail` |
| `500` | 服务内部错误 | 展示“分析暂时失败”，保留用户已填数据并允许重试 |

不要把 `NOT_PROVIDED` 当成接口失败；它表示请求成功但没有足够数据运行对应模块。
真实模式下禁止在错误后自动加载固定响应。固定响应必须由用户在联调控制台显式选择。

## 5. 本地联调与跨域

启动后端：

```powershell
cd backend
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

默认允许以下前端开发地址访问：

- `http://localhost:3000`
- `http://127.0.0.1:3000`
- `http://localhost:5173`
- `http://127.0.0.1:5173`

如果前端使用其他端口，启动后端前设置：

```powershell
$env:ICBC_CORS_ORIGINS="http://localhost:你的端口"
```

生产环境应填写确定的前端域名，不建议把跨域来源配置为 `*`。

## 6. 可直接使用的联调材料

- `api_examples/openapi.json`：完整机器可读接口契约。
- `api_examples/full_analysis_normal_request.json`：M001 正常场景请求。
- `api_examples/full_analysis_normal_response.json`：M001 正常场景响应。
- `api_examples/full_analysis_review_request.json`：M005 人工复核场景请求。
- `api_examples/full_analysis_review_response.json`：M005 人工复核场景响应。
- `../output/pdf/demo_materials/M001`、`M005`：营业执照、报表、计划和可选经营资产 PDF。
- `../outputs/material_upload_demo/M001`、`M005`：经营流水与纳税开票 Excel。

前端可以先读取固定响应完成页面开发，再切换到真实接口。若使用 TypeScript，可根据 `openapi.json` 自动生成类型，避免手写字段名称造成漂移。

## 7. 联调验收顺序

1. 用固定响应完成卡片、图表和空状态。
2. 调用 `/health` 确认后端在线。
3. 在材料页分别载入五份必交样例，确认每份出现编号、指标和主体匹配结果。
4. 使用正常场景请求调用 `/full-analysis`。
5. 使用人工复核场景检查风险状态、材料警告、规则和交易证据表。
6. 删除请求中的 `anomaly` 或 `cash_gap`，检查资料缺失空状态。
7. 故意删除一份必交材料，确认前端不能继续且后端返回 422。
8. 取消全部授权，确认提交按钮不可用且后端直接请求会返回 422。
9. 分别从商户入口和银行入口打开结果，确认商户端看不到内部规则，银行端能追溯材料编号和哈希。

接口字段如需调整，优先在 OpenAPI 契约和后端模型中修改，再重新导出样例，不要只修改某一份前端 mock 数据。
