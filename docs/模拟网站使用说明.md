# 融策模拟网站使用说明

> 适用版本：前端当前分支 + 后端 API v0.4.0  
> 使用场景：本地联调、队内验收、工行杯现场演示  
> 推荐演示模式：`真实后端` + `M001/M005` 仓库内置材料

## 1. 网站目前能演示什么

“融策”模拟网站展示了一笔小微商户动态授信申请从资料填写到银行审核的完整闭环：

1. 商户填写主体信息和申请需求；
2. 完成明确标注为演示的法人核验；
3. 上传五份必交经营材料，可额外上传一份补充材料；
4. 后端校验文件并生成可追溯的材料摘要；
5. 商户主动授权银行流水、平台经营和工商信息三类数据；
6. 后端统一运行经营信用评分、异常交易识别和资金缺口预测；
7. 在授信报告中查看商户摘要、消费承接与政策推荐；
8. 切换到银行审核台，查看评分门控、异常证据和流动性压力。

当前网页是竞赛 MVP，不构成正式授信承诺。页面中的额度和决策用于说明产品逻辑，最终授信仍应以银行正式审核为准。

## 2. 启动前准备

需要准备：

- Python 后端虚拟环境已经安装依赖；
- 前端已经执行过 `pnpm install`；
- 两个独立终端：一个运行后端，一个运行前端；
- 推荐使用 `8000` 作为后端端口、`5173` 作为前端端口。

仓库位置：

```text
D:\LQW\大一下\工行杯！\ICBC-conve-loan
```

## 3. 标准启动方式

### 3.1 启动后端

在第一个 PowerShell 终端中执行：

```powershell
cd "D:\LQW\大一下\工行杯！\ICBC-conve-loan\backend"
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

出现以下提示表示进程已经启动：

```text
Uvicorn running on http://127.0.0.1:8000
Application startup complete.
```

随后检查：

- 健康状态：<http://127.0.0.1:8000/health>
- Swagger：<http://127.0.0.1:8000/docs>

Swagger 页面应显示 API 版本 `0.4.0`，并且能看到 `application-materials` 分类及以下接口：

```text
POST /api/v1/materials/parse
GET  /api/v1/materials/demo/{merchant_id}/{group}
POST /api/v1/ml/full-analysis
```

如果 Swagger 显示 `0.3.0` 或完全没有材料接口，说明 `8000` 上仍然运行着旧后端，需要停止旧进程或改用其他端口。

### 3.2 启动前端

在第二个 PowerShell 终端中执行：

```powershell
cd "D:\LQW\大一下\工行杯！\ICBC-conve-loan\frontend"
pnpm dev -- --port 5173 --strictPort
```

启动后访问 <http://localhost:5173/>。首页可以选择 M001 正常授信或 M005 人工复核；第五步授信报告内可切换“商户摘要”和“银行审核台”。

## 4. 后端 8000 端口被占用时

如果 `8000` 被旧进程占用，可以把后端改到 `8001`：

```powershell
cd "D:\LQW\大一下\工行杯！\ICBC-conve-loan\backend"
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8001
```

然后在启动前端的同一个终端中先指定后端地址：

```powershell
cd "D:\LQW\大一下\工行杯！\ICBC-conve-loan\frontend"
$env:VITE_API_BASE_URL="http://127.0.0.1:8001"
pnpm dev -- --port 5173 --strictPort
```

`$env:VITE_API_BASE_URL=...` 只对当前终端有效，因此它必须和 `pnpm dev` 在同一个终端中执行。此时 Swagger 地址也要改成 <http://127.0.0.1:8001/docs>。

## 5. 后端调用方式

当前五步流程始终执行真实的前后端请求：

- 浏览器向后端下载仓库内置 PDF/Excel 样例；
- 浏览器把材料发送给材料解析接口；
- 后端校验扩展名、文件大小和文件签名；
- 后端计算材料 SHA256 摘要并生成材料编号；
- 页面调用 `/api/v1/ml/full-analysis` 获取综合分析结果；
- 请求失败时页面会保留当前申请并显示错误，不会偷偷切换到固定数据。

这里的“真实”指真实调用 FastAPI 接口，并不表示已经连接工行、税务、征信或平台生产系统。当前 OCR 与指标抽取使用明确标注的 M001/M005 竞赛模拟规则。后端离线或请求失败时，页面保留当前申请并显示错误，不会自动生成固定结果。

## 6. M001 正常授信案例演示

M001 用于展示资料完整、经营稳定、当前未发现显著风险的案例。

1. 打开 <http://localhost:5173/>。
2. 在首页“联调场景”选择 `M001 正常授信`，点击“开始在线测额”。
3. 在“基本信息上传”页检查预填信息；可选择自己的营业执照，也可以留到第三步载入样例。
4. 点击“下一页”，再点击“开始演示核验”；扫码弹窗出现约一秒后会显示核验完成。
5. 关闭弹窗并进入“经营数据”，依次点击每张材料卡片上的“载入 M001 样例”。如果第一步选择了营业执照，它会在这里自动解析。
6. 等待当前材料出现材料编号、完整度、抽取指标和“解析完成”状态，再载入下一份。
7. 五份必交材料全部完成后，页面进度应显示 `5 / 5`。建议同时载入第六份可选经营资产材料。
8. 点击“继续数据授权”。
9. 主动打开三项带 `*` 的可用数据来源：银行经营流水、美团订单与评价、公开工商信息。
10. 勾选“我已阅读并同意本次数据使用授权”。
11. 确认页面显示“后端服务在线”，点击“运行综合分析”。
12. 查看经营信用分、建议额度、经营画像、消费承接卡和政策推荐卡；再切换到“银行审核台”查看内部证据。

M001 的预期结果是“建议授信/低风险”方向。具体数值应以当前后端返回结果为准，不建议在演示讲稿中写死。

## 7. M005 人工复核案例演示

M005 用于展示系统不会只给出一个分数，而是能够把异常证据、材料警告和流动性压力带入银行复核。

1. 返回首页，选择 `M005 人工复核`。
2. 点击“开始在线测额”。
3. 完成主体资料和法人核验。
4. 在材料页依次载入五份 M005 必交样例，建议同时载入可选资产材料。
5. 留意材料卡片中的警告，例如主体不一致、申报月份缺失、个人账户占比较高、未来支出压力或租期较短。
6. 完成三项必需数据授权和总授权确认。
7. 点击“运行综合分析”。
8. 结果应进入“人工复核”方向，而不是自动拒绝。
9. 在授信报告切换到“银行审核台”，重点展示异常交易证据和 P50/P90 资金缺口；材料完整度和主体匹配结果可在第三步解析卡片中展示。

M005 说明异常识别模块负责提示风险和提供证据，不直接代替银行作出拒贷决定。

## 8. 材料提交页怎么理解

五份必交材料为：

| 材料 | 作用 |
|---|---|
| 经营主体证明 | 核验主体名称、信用代码和经营状态 |
| 经营现金流 | 支持经营稳定性、异常交易和资金缺口分析 |
| 资产负债资料 | 支持偿债能力和流动性判断 |
| 纳税与开票资料 | 与经营流水进行真实性交叉验证 |
| 经营与资金计划 | 把未来资本开支和偿债安排纳入压力预测 |

“租赁或经营资产证明”是可选补充材料，只用于增强经营真实性证据，不是信用贷必须提供的抵押物。

材料页有两种操作方式，第一步还可以提前选择营业执照：

- 点击“选择文件”或拖拽本地文件：测试真实上传交互；
- 点击“载入 M001/M005 样例”：从后端下载仓库内置文件，再自动提交解析；
- 第一步选择营业执照：进入第三步后自动提交后端解析，并显示在经营主体证明卡片中。

每个文件不能超过 5 MB。切换 M001/M005 案例或修改主体时，已经解析的材料会被清空，需要按新主体重新载入，避免证据链串户。

## 9. 授信报告的两种视图

### 商户端

商户端重点展示：

- 综合授信结果；
- 经营信用分与建议额度；
- 当前风险提示；
- 经营画像；
- 消费承接和政策申请推荐。

商户端不会展示银行内部审核规则和完整交易证据，避免把内部风控逻辑直接暴露给申请人。

### 银行审核端

在第五步授信报告顶部点击“银行审核台”，会额外展示：

- 评分门控与人工审核规则；
- 异常交易命中项及证据交易编号；
- P50/P90 流动性压力；
- “建议通过”“要求补件”“维持人工复核”三种审核动作。

当前审核动作只保存在本次浏览器会话中，刷新或关闭页面后不保证保留。生产版本需要接入用户身份、角色权限和审核记录数据库。

## 10. 建议的比赛演示顺序

时间充足时建议按以下顺序展示：

1. 用 M001 走一遍商户申请，说明“资料一次提交、三类模型统一分析”；
2. 在材料页重点展示真实文件交互、材料编号和可追溯摘要；
3. 在 M001 结果页介绍经营信用分、建议额度、消费承接和政策推荐；
4. 用 M005 走到授信报告，再切换“银行审核台”展示异常交易和 P90 压力；
5. 点击“要求补件”或“维持人工复核”，说明模型提供证据，最终决策仍由银行审核；
6. 最后主动说明 MVP 边界和后续真实数据/OCR/权限系统的接入计划。

如果现场时间有限，可以提前在两个浏览器标签中分别准备 M001 商户摘要和 M005 银行审核台，但正式答辩前仍应完整跑一次真实后端流程。

## 11. 常见问题

### 11.1 页面提示“无法下载演示材料”

按顺序检查：

1. 后端终端是否仍在运行；
2. Swagger 是否为 `0.4.0`；
3. Swagger 是否有 `/api/v1/materials/demo/{merchant_id}/{group}`；
4. 前端的 `VITE_API_BASE_URL` 是否指向实际后端端口；
5. 是否同时启动了多个旧版后端。

### 11.2 前端自动切换到 5174

说明 `5173` 已被旧前端占用。推荐停止旧进程，再使用：

```powershell
pnpm dev -- --port 5173 --strictPort
```

如果必须使用 `5174`，需要在启动后端前允许该来源：

```powershell
$env:ICBC_CORS_ORIGINS="http://localhost:5173,http://127.0.0.1:5173,http://localhost:5174,http://127.0.0.1:5174"
.\venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

### 11.3 8000 显示被不存在的 PID 占用

先通过以下命令确认：

```powershell
netstat -ano | findstr ":8000"
```

如果 `taskkill` 已找不到该 PID，但 `netstat` 仍显示监听，可以临时改用 `8001`，并按第 4 节设置前端地址。重启 Windows 通常也会清除残留监听。

### 11.4 授权页的分析按钮不能点击

需要同时满足：

- 主体信息完整；
- 法人演示核验已完成；
- 五份必交材料均已解析；
- 三项带 `*` 的可用数据来源均已授权；
- 已勾选总授权确认。

### 11.5 上传自己的文件后，为什么仍显示模拟解析

当前版本会真实传输和校验文件，并计算材料摘要；但 OCR、表格字段识别和业务指标抽取还没有接入通用解析模型，仍根据所选 M001/M005 场景生成明确标注的模拟指标。后续需要真实脱敏样本、标签体系和文档解析能力才能替换。

## 12. 演示时应主动说明的 MVP 边界

- 法人核验是交互演示，不采集或上传人脸影像；
- 材料文件会真实进入后端校验，但 OCR 和指标提取为竞赛模拟；
- 三项数据授权展示的是授权流程，尚未连接真实外部生产数据源；
- 当前违约概率没有真实历史标签校准，页面不会把经营信用分冒充为 PD；
- 审核动作尚未写入数据库；
- 页面结果不构成正式授信承诺。

这些边界不是演示缺陷，而是为了让评委清楚区分“当前已实现的工程闭环”和“需要真实银行数据及合规系统后才能落地的能力”。
