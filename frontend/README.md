# 融策前端

基于 React、TypeScript 与 Vite 的小微动态授信演示前端，使用后端 v0.4.0 契约。

## 授信流程

1. 企业主体与申请需求校验；
2. 法人核验演示；
3. 五份必交材料真实上传或一键载入，并完成模拟解析；
4. 三项 MVP 数据来源主动授权；
5. 调用 `POST /api/v1/ml/full-analysis`；
6. 根据 `overall_decision` 展示最终动作。

主体资料、核验状态、材料证据、资料组、授权来源、授权时间会共同形成请求。接口失败时保留当前状态，不生成任何授信结果。

材料页支持拖拽/选择 PDF、Excel、CSV、Word 或图片，单份上限 5 MB；“载入样例”会先从后端下载仓库内置文件，再调用 `POST /api/v1/materials/parse`。解析后的材料编号、哈希、完整度和主体匹配结果会随 `/full-analysis` 进入商户摘要和银行证据链。

## 启动

```powershell
cd frontend
pnpm install
pnpm dev
```

默认前端为 `http://localhost:5173`，默认后端为 `http://127.0.0.1:8000`。可复制 `.env.example` 修改后端地址。

## 三个入口

| URL | 用途 |
|---|---|
| `http://localhost:5173/` | 商户申请端，不显示内部审核证据 |
| `http://localhost:5173/?demo=1` | 商户端联调控制台，可显式选择 M001/M005 和真实/固定模式 |
| `http://localhost:5173/?portal=reviewer` | 独立银行审核演示入口，只显示内部审核台 |

银行入口的 URL 隔离只用于竞赛 MVP。生产环境必须由银行身份认证、角色权限和审核记录接口保护。

## 真实模式与固定模式

- 默认“真实后端”：每次提交前重新检查 `/health`，成功后才展示报告；
- “固定样例”只能在联调控制台中主动选择；
- 422、超时、离线和 500 均保留当前申请状态并显示错误，不会自动回退；
- 固定样例报告会明确标记“固定联调样例”。

## 当前 MVP 边界

- 文件会真实传入后端完成文件级校验；OCR 和指标提取仍是明确标注的 M001/M005 模拟规则；
- 法人核验为明确标注的演示状态，不采集影像；
- 银行审核动作保存在当前浏览器会话，尚未落库；
- PDF/LLM 报告生成尚未接入；
- `pd_12m = null` 显示为“待真实历史数据校准”。
