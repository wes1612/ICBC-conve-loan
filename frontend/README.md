# 融策前端

基于 React、TypeScript 与 Vite 的小微动态授信演示前端；首次授信沿用 v0.4.0 分析契约，贷后监测使用 v0.5.0 新增接口。

## 授信流程

1. 基本信息上传：填写企业、经营地址、法人、联系人和申请金额，可提前选择营业执照；
2. 身份核验：完成法人扫码/人脸核验演示；
3. 经营数据：五份必交材料真实上传或一键载入，并完成模拟解析；
4. 相关数据授权：主动授权三项 MVP 数据来源，再调用 `POST /api/v1/ml/full-analysis`；
5. 授信报告：展示队友设计的商户摘要、银行审核台、消费承接卡和政策推荐卡。

主体资料、核验状态、材料证据、资料组、授权来源、授权时间会共同形成请求。接口失败时保留当前状态，不生成任何授信结果。

材料页支持拖拽/选择 PDF、Excel、CSV、Word 或图片，单份上限 5 MB；“载入样例”会先从后端下载仓库内置文件，再调用 `POST /api/v1/materials/parse`。第一步选择的营业执照会在进入第三步时自动提交解析；解析后的材料编号、哈希、完整度和主体匹配结果会随 `/full-analysis` 进入后端审核证据。

## 启动

```powershell
cd frontend
pnpm install
pnpm dev
```

默认前端为 `http://localhost:5173`，默认后端为 `http://127.0.0.1:8000`。可复制 `.env.example` 修改后端地址。

## 演示入口

| URL | 用途 |
|---|---|
| `http://localhost:5173/` | 完整五步授信演示，可选择 M001/M005 |

第五步报告可在“商户摘要”和“银行审核台”之间切换。该切换只用于竞赛 MVP；生产环境必须由银行身份认证、角色权限和审核记录接口保护。

顶部“贷后监测”是首次授信之外的独立入口，提供银行贷后监测台和商户补充端。可切换 M001–M005，推进 12 个月轨迹、批准动态额度建议、模拟续期平台授权和提交补充材料。详细操作见 `../docs/贷后全周期动态授信使用说明.md`。

## 后端调用原则

- 当前流程始终使用真实后端：每次提交前重新检查 `/health`，成功后才展示报告；
- 422、超时、离线和 500 均保留当前申请状态并显示错误，不会自动回退到固定结果；
- M001/M005 是两套仓库内置演示材料与模拟业务指标，不代表真实银行或税务生产数据。

## 当前 MVP 边界

- 文件会真实传入后端完成文件级校验；OCR 和指标提取仍是明确标注的 M001/M005 模拟规则；
- 法人核验为明确标注的演示状态，不采集影像；
- 首次授信报告中的银行审核动作仍是原型；贷后监测的审核动作已接入进程内演示状态，但尚未持久化到生产数据库；
- PDF/LLM 报告生成尚未接入；
- `pd_12m = null` 显示为“待真实历史数据校准”。
