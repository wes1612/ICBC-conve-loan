# Data

## `数据字典_完善版__含评分规则与消费承接能力_v5.xlsx`

当前开发基线为 v5；v4 仅保留作历史版本。v5 新增评价数/订单数比交叉验证及人工审核规则 V09，评分与风控实现应以 v5 为准。

字段定义 + 评分规则 + 额度规则 + 人工审核规则，共9个sheet：

| Sheet | 内容 |
|---|---|
| Input_Data_Structural | 商户需提交/授权的原始结构化字段 |
| Operating_Structural | 由原始字段计算出的结构化中间变量与四个子评分公式 |
| Input_Unstructural | 商户需提交/授权的原始非结构化字段（评价/社媒/投诉） |
| operating unstructural | 非结构化中间变量与子评分公式 |
| Outputs | 报告输出字段（含AI智能解释模块） |
| 评分规则_打分卡 | 每个变量的打分区间和权重，可直接翻译成代码 |
| 额度映射规则 | 综合分→倍数、成长性扩张加成、最终额度公式 |
| 人工审核规则 | 一票否决（V01-V09）+ 低置信度转人工（L01-L04） |
| Consumption_Matching_Strategy | 消费场景匹配规则 |

## `五个测试商户_结构化与非结构化数据.xlsx`

5个覆盖不同画像的测试商户（优质稳定型/成长型/风险型/数据缺失型/疑似异常型），
每个商户的原始数据 + 精确计算的中间变量、子评分、综合分、额度、置信度、触发规则。
"预期输出对照表(最终版)" sheet是开发验收标准。

"测试商户总览" sheet里记录了几个已发现但尚未修复的评分规则问题（比如非结构化评分对"刷好评"型商户的
识别能力不足），实现评分引擎时建议一并处理，或至少不要引入新的类似问题。

## `ml_simulated/`

- `transactions.json`：五商户 553 笔模拟交易，包含 M003/M005 的可解释异常注入。
- `cashflow_monthly.json`：五商户连续 12 个月现金流及未来三个月计划支出。

上述文件用于异常识别、资金缺口预测的开发与接口验收。它们不是银行真实数据，不能用于声称已经训练真实违约或欺诈模型；生成方法和限制见 `ml_simulated/README.md`。
